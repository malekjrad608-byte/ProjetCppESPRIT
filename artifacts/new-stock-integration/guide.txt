3 Intégration  
Ce guide présente une méthode d’intégration collaborative pour le projet SmartMarket 
sous Qt + GitHub , visant à permettre à plusieurs étudiants de travailler simultanément 
tout en minimisant les conflits et en assurant la maintenabilité du code. 
L’essentiel pour réussir l’intégration est le suivant :    
• Travailler sur le projet intégré contenant toutes les interfaces graphiques. 
• Disposer d’un seul fichier .ui  (une seule classe d’interface graphique) qui 
regroupe toutes les pages et modules du projet. 
• Chaque étudiant ajoute et développe sa propre classe métier (Employé, Client, 
Produit, etc.) sur sa machine locale. 
• L’équipe se met d’accord sur la méthode d’intégration  afin de fusionner les 
changements et obtenir le projet final fonctionnel. 
Vous avez le choix entre deux approches : 
1. L’ancienne méthode, utilisée lors de l’intégration des interfaces : 
o Chaque module est déposé dans sa branche dédiée.

3.1 Structure du code : Règles de nommage, découpage par zones 
• Tous les boutons, labels, champs… doivent avoir des noms significatifs  
(btnAjouterEmp, lineEditNomClient, etc.). 
• Les boutons de navigation (menu, retour, etc.) sont programmés dans 
SmartMarket, pas dans les modules. 
• Structurer le code dans smartmarket.cpp et smartmarket.h  en zones 
clairement délimitées par module. 
 
• Chaque étudiant travaille uniquement dans la section de son module (délimitée 
par les grands commentaires // === MODULE XXX ===). 
• Le code de navigation (on_btnMenu...) est géré dans la zone “SLOTS GÉNÉRAUX” .

3.3.1 Une branche par module

• Les modules sont ensuite fusionnés sur une branche finale d’intégration  pour 
obtenir le projet complet. 
• Toutes les étapes sont les mêmes  que celles du guide d’intégration des

• L’important : un seul .ui final contenant toutes les pages.

3.3.2 Une même branche pour tout le projet 
• Tous les étudiants travaillent sur la même branche (ex. integFinale, master, main) 
• Respect strict des bonnes pratiques : 
o Modifier uniquement sa zone de code (// === MODULE XXX ===) 
o Noms clairs pour boutons, labels, champs… 
o Tester avant de pousser 
o Faire systématiquement un git pull avant git push 
• Git fusionne automatiquement la plupart des changements. 
 
Le choix de la méthode dépend de la maîtrise de Git par l’équipe, de l’organisation et 
des contraintes spécifiques au projet. 
 
3.4 Étapes de travail collaboratif sur une même branche 
1. Récupérer la dernière version :   git pull origin integFinale 
Avant de commencer, assurez-vous d’avoir la dernière version du dépôt : 
• Cela synchronise votre dépôt local avec le dépôt distant. 
• Important : toujours faire ce pull avant de commencer à travailler pour éviter des 
conflits inutiles. 
2. Travailler uniquement sur votre module : 
• Ajouter/modifier uniquement dans votre zone (// === MODULE XXX ===) 
• Tester localement avant tout push 
• Ne touchez pas aux sections des autres pour éviter les conflits. 
 
3. Ajoutez et validez vos modifications : 
git add smartmarket.cpp smartmarket.h  
              git commit -m "Ajout des slots Employé" 
• git add : sélectionne les fichiers à inclure dans le commit. 
• git commit : enregistre vos changements localement avec un message clair et 
significatif.

Important : faites un commit après chaque modification importante, cela rend le

4. Récupérer les modifications des autres avant de pousser : 
                git pull origin integFinale 
• Git va tenter de fusionner vos modifications avec celles des autres. 
• Si personne n’a touché aux mêmes lignes, tout se passe automatiquement. 
 
• Si un conflit survient, Git marque les fichiers concernés comme suit : 
 
 
 
➢ Comment gérer un conflit : 
 
1- Ouvrez les fichiers en conflit dans Qt Creator. 
2- Identifiez votre section (celle sur laquelle vous travaillez). 
3- Supprimez les marqueurs de conflit (<<<<<<<, =======, >>>>>>>) et 
conservez uniquement votre code ou combinez correctement les 
deux versions en faisant appel à l’étudiant concerné si nécessaire. 
4- Sauvegardez le fichier. 
5- Répétez l’étape git add pour chaque fichier résolu : 
git add smartmarket.cpp smartmarket.h 
6- Faites un commit pour valider la résolution du conflit : 
git commit -m "Résolution des conflits sur smartmarket" 
 Très important pour les débutants : si vous ne refaites pas git add et git commit, Git ne saura pas 
que le conflit est résolu et vous ne pourrez pas pousser vos changements. 
5. Pousser vos changements :  git push origin integFinale 
Si tout s’est bien passé, vos changements sont maintenant disponibles pour les autres 
membres de l’équipe. 
3.5 Résumé clé pour les débutants  
✓ Toujours git pull avant de commencer. 
✓ Faites des commits clairs après chaque modification importante. 
✓ Si un conflit apparaît : résolvez-le, refaites git add, puis git commit. 
✓ Ensuite seulement, vous pouvez faire un git push.
